🕐 GET /jobs/partners/promptness

Retorna dados de pontualidade de atendimentos: datas/horas planejadas vs realizadas, origem, destino, status e campos operacionais.

1. Endpoint

GET /jobs/partners/promptness
Propriedade Valor
Autenticação Header x-api-key obrigatório
Paginação Cursor — até 100 registros/página via paginationToken
Cache 5 minutos por combinação de parâmetros da query
Ordenação _id ascendente

2. Query Parameters

Parâmetro Tipo Obrigatório Regra
startDate string Sim Formato dd/MM/yyyy — retorna atendimentos com início a partir desta data
paginationToken string Não Token retornado na resposta anterior. Omita para obter a primeira página.

3. Paginação

Modelo cursor-based com envelope paginado. Cada requisição retorna até 100 atendimentos. Para obter a próxima página, envie o paginationToken retornado na resposta anterior como parâmetro de query.

  • Primeira página: envie apenas startDate
  • Próximas páginas: envie startDate + paginationToken da resposta anterior
  • Parar quando isLastPage === true (ou quando paginationToken estiver ausente)

Envelope retornado:

{
  "data":            [ /* até 100 itens */ ],
  "count":           450,
  "isLastPage":      false,
  "paginationToken": "CLrnGxoGEICAgIAIGg5..."
}

count: retornado apenas na primeira página (quando paginationToken não é enviado). Representa o total de atendimentos que correspondem ao filtro.
paginationToken: presente na raiz da resposta enquanto houver mais páginas. Diferente de /jobs/partners/details/json, o token não aparece dentro de cada item — use sempre o valor retornado no envelope.

4. Shape de Cada Item em data

Campo Tipo Descrição
_id_atendimento string | null _id interno do atendimento (MongoDB)
id_atendimento number | null Identificador numérico do atendimento (jobId)
data_inicio_planejada string | null Data que deveria começar (dd/MM/yyyy)
hora_inicio_planejada string | null Hora que deveria começar (HH:mm)
data_inicio_realizada string | null Data que realmente começou
hora_inicio_realizada string | null Hora que realmente começou
data_fim_planejada string | null Data que deveria terminar
hora_fim_planejada string | null Hora que deveria terminar
data_fim_realizada string | null Data que terminou de fato
hora_fim_realizada string | null Hora que terminou de fato
origem string | null Endereço completo de partida
cidade_origem string | null Cidade do ponto de partida
destino string | null Endereço completo de chegada
cidade_destino string | null Cidade do ponto de chegada
ultimo_status string | null Status do atendimento (ex.: FINISHED, CANCELED)
objetos_de_custo string | null Centros de custo separados por vírgula
tipo_de_viagem string | null Categoria (ex.: DEDICADO)
centro_de_planejamento string | null Centros de planejamento das solicitações associadas ao atendimento
placa_veiculo string | null Placa do veículo que realizou o atendimento
modelo_veiculo string | null Modelo do veículo que realizou o atendimento

Formatação: datas em dd/MM/yyyy · horas em HH:mm · campos sem valor retornam null · objetos_de_custo e centro_de_planejamento são strings com itens separados por vírgula.

5.2 Próxima página (usando o token da resposta anterior)

curl -G "https://<host>/jobs/partners/promptness" \
  --data-urlencode "startDate=27/04/2026" \
  --data-urlencode "paginationToken=CLrnGxoGEICAgIAIGg5..." \
  -H "x-api-key: $X_API_KEY"

Resposta (200) — página intermediária:

{
  "data": [ /* até 100 itens */ ],
  "isLastPage": false,
  "paginationToken": "CLrnGxoGEICAgIAIGg5b..."
}

Resposta (200) — última página:

{
  "data": [ /* itens restantes (< 100) */ ],
  "isLastPage": true
}

6. Erros Comuns

HTTP Cenário Mensagem
400 startDate ausente É necessário informar uma data para filtragem
400 startDate em formato inválido A data precisa estar no formato dd/mm/yyyy
401 API key inválida ou ausente Chave inválida
401 API key expirada Chave expirada
500 Erro interno Mensagem variável
