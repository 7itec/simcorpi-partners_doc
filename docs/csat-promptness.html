GET /csats/promptness

Retorna avaliações de CSAT (pesquisas de satisfação) relacionadas a atendimentos, filtradas por data de início do atendimento. Uso típico: medir qualidade percebida e satisfação dos passageiros ao longo do tempo.

1. Endpoint

GET /csats/promptness
Propriedade Valor
Autenticação Header x-api-key obrigatório
Paginação Offset (page / limit)
Cache 5 minutos por combinação de query + paginação
Ordenação createdAt ascendente

2. Query Parameters

Parâmetro Tipo Obrigatório Regra
startDate string Sim Formato dd/MM/yyyy (validado por regex)
page number Sim Inteiro >= 0 (começa em 0)
limit number Sim Inteiro entre 1 e 1 000

3. Paginação

Modelo offset com envelope paginado:

  • skip = page * limit
  • Próxima página: page + 1
  • Parar quando isLastPage === true

Envelope retornado:

{
  "data":        [ /* itens */ ],
  "count":       100,
  "currentPage": 0,
  "isLastPage":  false
}

Cache: a resposta fica em cache por 5 minutos, chaveada por (query + paginação). Trocar qualquer parâmetro gera uma chave de cache diferente. Mudanças no banco podem demorar até 5 minutos para refletir.

4. Shape de Cada Item em data

Campo Tipo Descrição
id_do_atendimento string | null _id interno do atendimento
data_de_inicio string | null Data no formato dd/MM/yyyy
motorista string | null Nome do motorista que conduziu
passageiro string | null Nome do passageiro que avaliou
avaliacao number | null Score do CSAT (escala 1 a 5)
placa_do_veiculo string | null Placa do veículo
modelo_do_veiculo string | null Modelo do veículo
endereco_de_origem string | null Endereço de origem formatado
endereco_de_destino string | null Endereço de destino formatado
nome_da_empresa string | null Empresa associada ao atendimento
tipo_de_servico string | null Tipo de serviço do atendimento (ex.: DEDICADO)
prestador_de_servico string | null Empresa prestadora
justificativa string | null Comentário escrito pelo passageiro no CSAT

5. Exemplos

5.1 Requisição de sucesso

curl -G "https://<host>/csats/promptness" \
  --data-urlencode "startDate=27/04/2026" \
  --data-urlencode "page=0" \
  --data-urlencode "limit=2" \
  -H "x-api-key: $X_API_KEY"

6. Erros Comuns

HTTP Cenário Mensagem
400 startDate ausente É necessário informar uma data para filtragem
400 startDate em formato errado (ex.: ISO) A data precisa estar no formato dd/mm/yyyy
400 page ou limit inválidos Mensagem do validador
401 API key inválida ou ausente Chave inválida
401 API key expirada Chave expirada
500 Erro interno do servidor Mensagem variável
